# Topic 內容與七語系審查記錄

這份記錄區分兩件事：`scripts/review-topic-content.mjs` 是可重跑的自動守門器；七個代表市場人格則是內容編輯時使用的人工閱讀角度。自動守門器不能冒充真人語言專家，也不能單靠欄位存在就宣稱「零建議」。

## 七個人格的人工閱讀角度

| 人格 | 審查焦點 |
| --- | --- |
| 台灣 | 七夕、鬼月、中元、返鄉與在地日期，不把台灣經驗寫成全球規則 |
| 日本 | 情人節／白色情人節、正月、盂蘭盆、節分與地域差異 |
| 中國 | 農曆／公曆、中秋、清明、中元與地方差異 |
| 印度 | Diwali、Pongal、Valentine Week 的區域、宗教、城市與家庭差異 |
| 印尼 | Idul Fitri、mudik、日期變動與不返鄉的個人選擇 |
| 巴西 | Dia dos Namorados、Festas Juninas、Réveillon、聖誕與獨立日的在地語境 |
| 美國 | federal holiday、文化節日、家庭選擇與歷史爭議的界線 |

## 內容規則

- 每個語系的標題要出現使用者認得的節日或生活詞；不可只用「保護與遊戲」這類抽象分類名。
- summary 要先講清楚實際收錄的節日，再說它們共享的社會現象；不可用空泛的全球化句型帶過。
- customs 要寫具體行為、參與者和地方脈絡；不可每國都套用「列三項習俗，再補一句不是所有人都如此」的模板。
- 不保留未翻譯的 `Topic`、機械直譯或社會學論文式抽象語句。
- 同一節日可以出現在多個 Topic，但每次必須有不同且可讀的共同性視角。

## 修正輪次

- Round 1：修正舊資料的單一日期模型、observance 唯一鍵、合併情人節入口與 Topic 主圖。
- Round 2：建立 52 週排程、七語系欄位與來源驗收；這一輪只是結構檢查，不能算語言專家審核。
- Round 3：全面重寫 9 個 Topic 的七語系 title、summary、keywords、customs 與 commonality；把抽象標題改為「情人節、七夕與白色情人節」、「鬼節：鬼月、中元與節分」、「元宵、排燈節與聖誕燈火」等可辨識入口。
- Round 3 同步讓自動守門器檢查標題辨識度、未翻譯字樣與已知舊模板，並明確輸出「自動守門通過」，不再冒充七位真人簽核。
